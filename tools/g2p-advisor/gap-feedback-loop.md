# Gap & Feedback Loop

How the Advisor feeds knowledge gaps back into the documentation. The Advisor is a *viewer* on the wiki; when it can't answer something well, that's a signal to improve the underlying knowledge. This page covers the two ways gaps are discovered on the Advisor side and how they flow to the wiki's triage pipeline.

For the wiki side of the same pipeline (generating question banks and triaging gaps into sinks), see [WikiLLM — Elicitation § Persona elicitation](../g2p-wikillm/elicitation.md#persona-elicitation--testing-the-live-advisor).

## Two gap producers on the Advisor

### 1. Persona harness (`npm run persona`) — proactive

Instead of waiting for real users to hit holes, an AI persona asks the questions its audience actually asks and runs each through the **real Advisor answer path** (the exact `chatSystemPrompt` + tool loop + wiki retrieval the web app uses). A critic then grades each answer.

```bash
npm run persona -- operator                 # full operator bank
npm run persona -- operator --limit 5
npm run persona -- operator --only spar-ops.partner-api-update-fa#1
```

* The **question bank** is generated by the wiki (`elicit:persona-generate`) from the persona's taxonomy areas, and read from `$WIKI_PATH/elicitation/personas/<persona>.json` (falls back to a local `data/personas/<persona>.json`).
* Each weak answer (critic verdict `partial` or `failed`) becomes a `GapRecord` written to `data/persona-gaps/<persona>.json`, carrying the **retrieval trace** — which wiki pages ranked and which the model actually opened.
* Because it exercises the real path, the bank doubles as a **regression / eval set**: run it against two models and compare pass rates.

### 2. Answer feedback (`answer_feedback` table) — reactive

Every Chat/Project answer can be rated 👍/👎 with an optional "suggest an improvement" note. Feedback is stored in Postgres (`answer_feedback`, migration `0004`) **with the retrieval trace and model**, so a gap can later be classified without re-running the query. This is the *real-traffic* producer — it accumulates as operators actually use the Advisor. *(The capture table exists; the in-app 👍/👎 UI is in progress.)*

## The provider rule

The persona harness uses **two** LLM steps on **different** providers, and this split is deliberate:

| Step | Provider | Why |
|---|---|---|
| **Answerer** (Advisor answers the question) | OpenRouter API (e.g. `deepseek/deepseek-chat`) | Must reproduce exactly what a real Advisor user gets. |
| **Critic** (judges the answer) | Claude CLI (subscription) | Offline QA, not a user-facing reply — free and a stronger judge. Set `PERSONA_CRITIC_MODEL` (default `sonnet`). |

Rule of thumb across both tools: *"am I imitating the deployed Advisor's reply?"* → API; otherwise → Claude CLI.

## Where gaps go

Gap records from both producers are collected and triaged by the wiki's `elicit:triage` into one of three **sinks** — `source-fix` (write docs → the only sink that earns a Documentation-epic Jira), `synthesis-fix` (fix the wiki synthesis prompt, no ticket), or `lesson` (capture tacit knowledge). Nothing stays in the gap ledger permanently; the knowledge lands in the docs, the synthesis prompt, or a lesson.
