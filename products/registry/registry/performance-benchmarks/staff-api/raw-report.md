# Raw Report

Every measurement Locust actually recorded, verbatim: no curation to a headline endpoint set, no SLO comparison, no PASS/FAIL. That interpretation lives in the [final report](final-report.md), built from this data.

{% file src="../../../../../.gitbook/assets/registry-staff-api-raw-report.zip" %}
The full raw report (Markdown, 7 MB uncompressed, 91 tables), zipped.
{% endfile %}

{% hint style="info" %}
The raw report is published as a download, not as a page: at this size GitBook cannot render it, and a page that fails to parse stops the documentation from syncing. It is generated by `performance-testing/scripts/create_raw_report.py` in the [Farmer Registry repository](https://github.com/openg2p/farmer-registry/tree/develop/performance-testing) from the Locust results (`locust/api/results/staff-api/`); re-run it after a new test run rather than editing the report by hand.
{% endhint %}

## What it contains

One table per ingress, volume tier, pod scale and test step (and per scenario for step 1), with the columns from Locust's own statistics: request and failure counts, response times (median, average, min, max and percentiles p50 to p100), content size, and requests and failures per second.

- End-to-End
  - Volume-Tier: `primary`
  - Volume-Tier: `smoke`
  - Volume-Tier: `stretch`
- In-Cluster
  - Volume-Tier: `primary`
  - Volume-Tier: `stretch`
